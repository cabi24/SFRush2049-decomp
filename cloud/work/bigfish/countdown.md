# countdown (0x800FBF88, 668 words) - feasibility: LOW-MEDIUM (best of the four)

- Exact target: `.text.countdown` in asm/us/blob/blob_800f8d9c.s, 668 words, 0x800FBF88..0x800FC9F8, first word 0x3C028011 (`lui v0,0x8011`), then `lw v0,29876(v0)`, `addiu sp,-24`. (Frame is tiny: 24 bytes; all state lives in globals and s0-s6.)
- Spliced? No; only prototypes in src/blob headers. Note the historical label is wrong: `countdown_handler` is 0x800FBC30, this function is the big state machine after it (race-start/loading countdown: 9x viScheduleTick, 4x viDeadlinePassed, race_setup_1/2, ghost_race_setup, records_screen, render_viewport_init, players_frame_update, memset).
- **ABI-shaped.** No arguments, called only from `game_loop`. No caller-save (t-reg) value crosses a `jal` in a crude scan; values live in s0-s6. Its callees `func_800F7F3C` (349w), `func_800FBE30` (12w, already in cloud/matches), `func_800B61A8` (21w), `func_800FBF2C` (23w) have countdown as their ONLY caller, so a small group (countdown as member, those four as context, ~1070 words total) would be the safe way to score it. `func_800C813C` (225w, 6 callers) is ABI (a0 only).
- Globals: many 0x8011xxxx mode/state words (`lw v0,29876(0x8011)` = 0x801174B4, stores to 0x801174BC/0x801174B8), about 25 refs into 0x8014/0x8015 (player/race state). Values not yet named.
- Shape: flag tests (`sll t6,v0,0xd; bgez` bit tests of a mode word), init_state_begin/continue, then a per-frame loop with timing (`viGetTimeToDeadline` float + `trunc.w.s`), 3-way switch-like `li at,N; bne` chains, calls out to menu/setup functions.
- First pass: `seeds/countdown.m2c.c` (337 lines). Compiled with `-g0 -O2 -mips2 -G 0 -non_shared -Wab,-r4300_mul` after K&R-ising the extern prototypes: emits ~689 words vs 668 target; opcode-aligned LCS 513/668 (76%); exact relocated-word LCS 198/668. Size is within 3%, which is unusually close for an m2c seed.
- Verdict: LOW-MEDIUM. Closest size and no IPA parameter. Needs careful hand restructuring (the m2c form is goto-heavy) and a proper struct for the 0x8011/0x8014 state. Realistically many hours; a full 668-word match is still unlikely without a permuter run.
