# The game was assembled with `-r4300_mul`

Found 2026-09-29 (cloud Lane A). **Action for maintainers:** add `-r4300_mul`
to the `as1` step of `tools/cloud/score.py` (`compile_group`) and
`-Wab,-r4300_mul` to the single-function `cc` compile, and the same to the
Conveyor toolkit's compile/score jobs. (Not changed here: `score.py` is the
maintainers' file.)

## Evidence

- Across all game-code targets (`asm/us/blob/`), **no function contains two
  adjacent single/double FP multiplies**, and **90 functions contain
  `mul; nop; mul`**. The original toolchain always separated them.
- That is IDO's VR4300 multiply-errata workaround: `as1 -r4300_mul` (from
  `cc`: `-Wab,-r4300_mul`), which the N64 SDK builds use.
- With `as1 -r4300_mul` added to the group pipeline, and no source change:
  - `MP_TargetSteerPos`: 44/103 -> **MATCH**;
  - `func_800B9B64`: 100/129 -> 2/129.
- None of the 348 locked matches contains the pattern (0 of the 90 are
  matched), so adding the flag cannot change them: it only inserts a `nop`
  between back-to-back multiplies, and a matching body has none.

## Affected work

- All 90 functions are unmatchable without the flag. None are in
  `cloud/work/near-miss/`.
- IPA groups with affected members: `func_800E92C8`, `func_800E56F8`,
  `func_800B9B64`, `func_800E681C`, `func_800AD4C8`, `MP_TargetSteerPos`,
  `func_800E4300`.
- The m2c/permuter sweeps should be rescored for these 90 with the flag;
  some "near" results may already be exact.

## How it was found

Two unrelated groups (`MP_TargetSteerPos`, `func_800B9B64`) were each one
`nop` short after a `mul.s` with otherwise identical code. Varying `as1`,
`ugen`, `uopt` optimization levels, `-mips1/2/3`, and swapping in IDO 7.1's
back end changed nothing; a scan of every target for adjacent multiplies
showed the systematic pattern.
