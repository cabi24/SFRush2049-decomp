# Spatial-cell visibility reconstruction

Research frozen; not accepted. `physics_float_calc` at 0x8009EBC0 contains 294 native instructions (1,176 bytes). The historical name is misleading: this routine updates scene-object visibility from a spatial-cell mask.

The actual caller passes an integer player/view index, a position vector, and an integer force-visible flag through the ordinary argument registers. The first argument is saved but unused by the native body. There are no hidden register inputs and no native calls. The square root is an actual single-precision intrinsic.

The routine follows a chain of 104-byte cells, measures the position relative to each cell origin, checks five actual bounding conditions, and chooses the nearest matching cell. A high vertical position adds a distance penalty. Native also computes a nearest-cell array index that is not subsequently consumed; the reconstruction retains this real calculation. It chooses one of nineteen genuine visibility-mask arrays, then updates bit31 of consecutive 68-byte scene-object records. The global override hides objects even when their mask bit or the force-visible argument would show them.

All nineteen native switch-table entries have been decoded independently and lead to the consecutive nineteen case bodies in the baseline. The complete source-built jump table still requires protected verification. When no cell matches, the genuine fallback mask is used. An invalid track ID after a successful cell match leaves the mask pointer undefined in the native routine; the source preserves that control path without inventing an initialized value.

No direct arcade ancestor has been identified. The arcade visibility names found so far refer to a different car-quad visibility check. Source layout and compiler controls will be judged against the entire native body and its real switch table. Raw objects and disassembly remain under ignored `build/large_visibility_cell`.

The initial full baseline has 336 padded words and 209 aligned opcodes under O1; native has 294 executable words and a136-byte frame. Actual accepted2D-length helper and genuine vector-subtraction contexts do not resolve the remaining structure. These results are research evidence only; no function or switch table has been accepted.
