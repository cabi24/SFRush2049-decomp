# Vehicle tire forces reconstruction

Research in progress; not accepted. Target func_800E23A4 is the full 422-instruction, 1,688-byte vehicle force updater. Its direct arcade ancestor is forces1 in reference/repos/rushtherock/game/drivsym.c, beginning around line 391. The function has one actual vehicle-model pointer argument and ordinary callee ABI calls.

The body computes four tire coordinate frames and velocities with calctireuv (historical camera_collision_avoid), then four wheel forces with dotireforce (historical camera_follow_target). It discounts front longitudinal drag by throttle, optionally applies a direction-force helper, updates wind forces and relative air speed, calculates rolling and aerodynamic drag, applies per-surface drag scaling, and adds drag from dirt, pavement, or slip. Every native branch is retained.

N64 changes include z as the longitudinal vehicle axis, four explicit calctireuv and dotireforce calls, fourteen dotireforce arguments instead of the arcade fifteen, a real traction predicate for rear calls, a genuine wheel-zero reference in one rear predicate branch, extra wind and drag conditions, integer player/selection records, and disabled arcade game-over drag logic. Native literals are 5000.0f and two distinct source-owned 0.1f pool entries. Independent protected relocation of the complete genuine O3 group now proves all twelve literal-pool bytes and all six pool reference sites against the native image.

Original donor direct field arguments remove manually introduced pointer locals and reduce the frame from 192 to 144 bytes. Keeping the actual consumed donor poortract and airfact values recovers the native 152-byte frame. Retaining all original unused donor declarations gives a 168-byte frame and does not improve instructions, so these unused declarations are excluded from the current source. Explicit pointer interleaving recovered native address homes but duplicated local storage and is retained only as a diagnostic control.
