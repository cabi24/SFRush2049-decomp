# Seven sequence-context promotion adapters

This packet repairs the shared-type conflicts for `func_80017540`,
`func_80018A30`, `func_80018B3C`, `func_80018C2C`, `func_80018D40`,
`func_80019194`, and `func_800198C8`: **1,596 candidate bytes**.

Base: `cf10b3392d7f00ae42d75c008b79fdc2541aab6b`.
Scope: `src/rom/lib_17dc0.c` only. PR #82's separate twelve repairs are not
included. No production TU, source lock, target, pinned context, symbol map,
scorer, compiler flag, remote builder, or promotion state is changed.
**No additional matching or ROM coverage is claimed.**

## Why this is an adapter rather than a production refactor

The accepted `AudioState` covers only the prefix through F7C. It cannot serve as
an array element: its apparent extent is F80, while the native stride is FF8.
`ContextPrefix` exposes the same lists under different field names, and the
accepted `VoiceRecord` supplies the full stride but hides timing and list fields.
The seven sources introduce still more views of the same objects.

`sequence_context.h` reconciles the actually observed fields into one native
`SequenceContext` shared by both globals and the real list helpers. It uses
ordinary pointers, naturally aligned records, and genuine unmodeled object
ranges. There are no artificial unions, pointer-view casts, macro field aliases,
extra arguments, keepers, inline assembly, or padding introduced to affect code
generation.

Consolidation changes the source text of six already accepted functions even
though every generated byte remains identical: 1729C, 1734C, 173B4, 17410, 17470,
and 174D0 (all prefixed `func_800`). Five need type spelling changes; 1734C also
uses the common `active`/`pending` list member names. Replacing these bodies in
production while leaving their locks unchanged would create stale locks.
Therefore this packet leaves production untouched. `verify.py:adapt_context`
creates the canonical refactor in a temporary copy of the complete real TU.
The seven `sources/*.c` files are explicit standalone adapters, not claims or
replacements for the frozen input sources.

## Native layout and ABI evidence

The evidence files and their SHA-256 hashes are listed in `verification.json`.
Only descriptions and hashes are published, not native instruction dumps.

- `800198C8` iterates exactly eight records, advancing by 0xFF8. It assigns each
  element address of `D_80043EB8` directly to `D_8004BE80` before calling the
  no-argument service helpers. Eight records end at 0x8004BE78, the observed
  adjacent index word. This proves that the two globals refer to the same full
  record, not independently sized objects.
- `800171C0` initializes doubly linked nodes with a 0x18 stride. List consumers
  use next/previous at 0/4 and `80017540` reads the unsigned handle at 8.
  `SequenceNode` therefore retains the remaining twelve genuine object bytes.
- `800178B0` forms a pointer from an input-data base plus an offset and stores it
  at both F68 and F6C; the null-offset path clears F68. `80018A30` dereferences
  F6C as an eight-byte `(unsigned time, unsigned value)` record and advances
  by eight. `80018B3C` resets the current pointer from the F68 start pointer,
  then resets the split timing words F70/F74. F68 is a pointer whose nullness
  gates processing, not a separate integer activity flag.
- `80018A30` compares unsigned time to highF74 + half120 and forwards the word
  assigned to rate124. The FFFFFFFF sentinel and unsigned ordering are retained.
  Its callback can change the global context: cursor advancement deliberately
  reloads `D_8004BE80`. No local cached context is substituted.
- The existing accepted list bodies prove F78/F7C, with `8001734C` consuming
  node identifiers from both lists. The consolidated prototypes take the actual
  record or node pointer used by these callees; no incompatible prefix cast is
  needed.
- Existing accepted `80017644`/`800190AC` plus the candidates establish unsigned
  identifier000, words110/114, byte flagsFC0/FC1, halfwordFC2, byte channelFC4,
  the 64 channel bytes at 528, valueFE0, wordsFE4/FE8, halfwordFEC, flagsFEE,
  and pending wordFF0. `layout_checks.c` independently enforces every modeled
  offset, the node/timed-entry strides, the 0xFF8 record stride, and 8-record
  extent under actual 32-bit IDO.
- Real `80019A60` takes `(u32, u8)`, including byte normalization of its second
  argument and unsigned rate arithmetic. `8001B9F8` takes `(u8, u16, u8, u8,
  u32)`; the fifth identifier occupies the genuine fifth O32 slot. The direct
  and 64-channel fan-out paths preserve the original identifier only for the
  primary call.
- `8001BDB8(u8)` and `80018184(void)` produce integer boolean results.
  `80018634(void)` and `80017D38(void)` return unsigned bytes, explicitly loaded
  as bytes by their native epilogues. The service caller retains its real
  byte-valued locals and the low-byte conversion of the integer third result.
- The accepted `800201D0(u32)` returns the original unsigned identifier or
  FFFFFFFF. Its old `int` declaration is corrected to `unsigned int`, with an
  explicit unsigned sentinel comparison. No caller ABI slot or instruction is
  added. The no-argument service functions remain no-argument declarations.

## Reproduce locally

Use the repository's pinned IDO compiler and MIPS binutils, with `IDO_DIR` and
`PATH` configured for those tools. No private ROM is needed for these checks.

```sh
python3 cloud/work/boot_tail_promotion/sequence_context_contract/verify.py
REQUIRE_TOOLCHAIN=1 python3 -m pytest -q tests/cloud/test_sequence_context_contract.py
```

These explicit checks are necessary: changed-submission CI does not select this
adapter directory. The verifier writes only beneath `--out` (default
`build/sequence_context_contract`), restores scorer module state, and never calls
a promotion or remote-builder command. Its frozen baseline is a historical
control; the current-production check discovers current accepted locks and
allows additional valid promotions. Already overlaid candidate bodies are not
inserted twice, and an already canonical TU is not adapted a second time.
