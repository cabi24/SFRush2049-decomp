# One whole-program build of every locked game body (experiment, 2026-10-04)

Question: if all 676 locked game-code bodies (543 standalone `-O2` singles + 133
members of 70 ad-hoc `-O3` groups) are compiled together as ONE whole-program
`-O3` `uld -kp` unit, how many still produce byte-identical code, and what
decides it?

Nothing under `src/blob`, `asm/`, `*.lock.json`, `tools/cloud/score.py` or
`tools/conveyor` was edited. All builds ran in an isolated copy on the builder
(`watchman2:~/rush2049/scratch/frontier/wholeprog`, a copy of `.../frontier/base`).
Nothing was committed.

## Answer in one paragraph

A single whole-program unit is **viable**: **675 of 676** locked bodies are
byte-identical in one 622-file unit (676 with files linked in descending address
order, where the last one happens to land on the right alignment), built in
**under 5 s** from scratch. But the keep list alone does not decide it, and
neither bracketing rule works: *keep everything* gives 572, *keep only roots*
446. What decides it is a small per-function manifest that the 70 groups already
encode piecemeal: (1) which ~100 functions are **internal** (the rest are kept;
the retail image is mostly ordinary global functions, not "everything internal"),
(2) which tiny callees must **not be inlined** (9 inline blockers), (3) one
definition per function (72 names are defined in several files today), and
(4) link order (reverse address order reproduces retail layout order). Kept
functions are insensitive to context: no standalone single changes because a
callee became visible, except through inlining of tiny callees.

How far the full set got: all of it. 622 source files (543 singles + 79 group
files), 923 function definitions, 810 distinct global functions (818 after
renaming stand-ins that share a name), of which 676 locked and 134 context-only
(43 stand-in callers). No file failed to compile and no stage failed.

Other measurements (tested):

- **Wall clock** (`WP_NOCACHE=1 WP_JOBS=1`, run `timing`): `cc -j` of all 622
  files serially 4.5 s; `uld` 0.03, `usplit` 0.01, `umerge` 0.02, `uopt` 0.13,
  `ugen` 0.02, `as1` 0.06 s; link-to-object 0.3 s. Object `.text` 165,728 bytes
  (retail: 1,216 functions, 561,008 bytes). Scoring 676 members through
  `score.compare` takes ~42 s and dominates; that is the scorer re-walking every
  relocation per member, not IDO.
- **Emission order** is not link order and not address order by default
  (name-sorted link: longest address-increasing subsequence 75 of 755). It is
  callee-before-caller (551-555 of 555 unit call edges, as S3 measured on
  retail) and otherwise **reverse link order**. Linking the 543 singles in
  descending address order (`singles_raddr`) emits them in address order:
  540 of 546 in sequence, 2 adjacent inversions, both from the one single file
  that defines five functions. The full unit linked that way: 613 of 755, 81
  inversions (multi-function group files and context functions).
  Without `umerge` the order is plain link order and callee-first is lost
  (434 of 555), so `umerge` ran on retail.
- **Absent (not yet decompiled) functions** cause no build problem: undefined
  externals stay as relocations through every stage. Their absence matters in
  three indirect ways, all seen below: missing callers of an internal function
  (it is inlined into its only visible caller or deleted), tiny callees that
  will start being inlined the day they are added, and text offsets that differ
  from retail (alignment-sensitive code).

## What decides it: mechanisms

Each is **tested** unless marked inferred.

**M1. Kept functions do not react to visible context, except through inlining.**
With every function kept and the 9 blockers (`ab_all`), 0 of the 543 singles
fail; all 102 failures are group members that need an internal callee or
internal linkage. So `-O2` standalone remains a valid recipe for a function that
is kept and whose callees are kept, and `-O2` vs `-O3` is irrelevant for it
(543 of 543 singles also match alone at `-O3`).

**M2. Interprocedural register effects exist only for internal (non-kept)
procedures.** Keep such a function and its callers lose the match, e.g.
`mode_byte_set` wants `move t0,zero` (IPA argument register) and gets
`move a0,zero`; `audio_helper` wants its argument in `a2` and gets `a1`.
Make a function internal that retail had global and it breaks instead:
with every function internal except true roots (`ab_real_si`) 221 singles
fail. So the retail image is mostly kept (global) functions with a minority of
internal ones. *Inferred:* the original keep list is not "entry points only".

**M3. `umerge` inlining rule** (`inline_rule.py`, synthetic, output in
`results/results_inline_rule.txt`): a callee is inlined at every call site,
kept or not, when its pre-optimisation body is tiny (0-2 simple statements, or
1 statement plus up to 2 calls; 3 statements, or 3 calls, are too many; a dead
`if (0)` block of 4+ statements counts as size). An internal callee with exactly one call site is inlined whatever its
size and its body is deleted. A kept callee keeps its body. The number of call
sites does not protect a tiny callee (1 to 9 call sites all inlined).

**M4. Retail did not inline several tiny callees that our sources make
inlinable.** `inline_edges.py` compares `umerge -v` with retail `jal`s: in
`full_groups` 15 caller/callee pairs are inlined although retail calls by
`jal` (callees `func_800BF01C`, `func_800D52CC` (both 2 words), `func_80096288`
(4), `audio_doppler`, `audio_distance_atten` (15), `object_byte9_set` (16),
`func_800A510C` (19), `mode_byte_set`, `mode_byte2_set` (20)), and 8 pairs are
inlined consistently with retail (retail caller has no `jal`; the callee body
still exists with zero callers, e.g. `func_80098710 <- func_800986DC`).
*Inferred:* the original source of those nine functions was larger before
optimisation (constant-false debug or arcade code); a standalone match of a
tiny function does not determine its inlinability. Appending a dead
`if (0) {...}` block to exactly those nine (`--block`, the trick the groups
already use by hand) fixes 11 members with no regression. `-noinline` is not
the answer: it loses the zlib members and others that need real inlining
(`ni_groups`).

**M5. Deleted procedures leave a `jr ra; nop` stub, and retail is full of
them.** An internal procedure whose calls were all inlined (or that has no
caller) is emitted as a 2-word stub. Retail contains 161 `jr ra; nop` bodies,
159 with no `jal` caller, all 159 currently locked as empty C functions
(`stubs.py`). In the zlib range the five retail stubs (`func_800A8D8C`,
`func_800A8D94`, `func_800A99C0`, `func_800AA44C`, `func_800AAB34`) sit exactly
where the group object emits the stubs of zlib's inlined statics
(`send_all_trees`, `copy_block`, `build_bl_tree`, `read_buf`, `tr_static_init`).
*Inferred:* most of the 159 are not empty functions but deleted internal
procedures whose code lives inlined in a nearby caller; each is a hint for the
matcher of the function that follows it.

**M6. Internal under `-kp` is the same as C `static` under the stock link.**
For all 48 single-file groups that have internal functions, marking the 120
non-kept functions `static` and linking with the driver's own
`uld -preserve_dead_code` (no keep list) gives a `.text` identical to the
group's `-kp` build, relocated fields masked (`static_equiv.py`: 48 of 48).
*Inferred:* the original may simply have been `cc -O3` over its files with
ordinary `static` functions. Address locality does not settle it
(`locality.py`: 72% of internal functions have all retail callers within 64 KB
versus 54% of kept ones, but bottom-up emission scatters a file's functions).

**M7. Duplicate definitions are silent.** `uld` prints "multiply defined ...
previous (used) ... new (ignored)" and exits 0; the first file wins and members
change (`mini.py dup`). 72 function names are defined in more than one file, 57
of them locked bodies that a group re-defines as context. The driver keeps one
definition per name (the locked one) and turns the others into prototypes;
stand-ins that share a name across groups are renamed per file.

**M8. Some code is position dependent.** `task_complete_signal` (an infinite
loop followed by an unreachable epilogue) gets 0 to 9 padding words before the
epilogue depending on its start offset (`mini.py padb0..4`: 45, 44, 42, 41, 40
words; target 36). Its group matches because an unrelated 17-word context
function puts it at the right offset. In a unit that is not laid out like
retail such functions fail spuriously.

## Recommendation

**A single whole-program build is viable as the canonical game build**, and it
is the only form in which the IPA component is consistent: today the same
function is defined up to several times with different bodies, signatures and
keep decisions across groups (M7), and those conflicts are invisible until the
bodies meet in one unit. It is not a drop-in switch, because the unit needs a
manifest that no single rule derives:

- internal set (100 functions in `best_*`: 58 group members, 6 locked singles,
  36 context) - evidence-driven, per function;
- inline blockers (9), derivable mechanically from retail `jal`s vs `umerge -v`;
- one definition per function, with the right signature;
- link order = descending address.

For the 543 kept singles the whole-program context changes nothing (M1), so
`-O2` standalone stays the right inner loop for ordinary functions; the
whole-program unit is the gate that keeps everything consistent and the place
where IPA members are matched without stand-in scaffolding being re-invented
per group.

Next concrete step: promote `wp.py build --keep groups --block ... --order
raddr` into a **shadow gate** (not yet the splice source): generate the
manifest (keep list `results/best_keep.txt`, blockers
`results/block_ab_groups.txt`, the three forced keeps, the `func_800BF01C`
definition) from the lock and group specs, build the unit on every lock change,
and fail on any member that stops matching. Then (1) resolve the 57
context-vs-locked duplicates at source so groups stop carrying private copies,
(2) replace the scorer's per-member relocation walk so the gate costs seconds,
(3) feed the unit object to the existing per-slice relocation
(`grouplink.py`, S4) and the image gate, and (4) only then retire per-group
builds. Separately, treat the 159 zero-caller stubs as "deleted internal
procedure" markers rather than empty functions when matching their neighbours.

Not tested here and still open: data-section order in a merged unit; whether
the unit object splices to the image hash (only word-level scoring was done);
whether a whole-unit build helps match any currently unmatched function.

## Commands

On the Pi (this directory):

```sh
./sync.sh        # rsync scripts to watchman2:rush2049/scratch/frontier/wholeprog/wp/
```

On the builder:

```sh
cp -r ~/rush2049/scratch/frontier/base ~/rush2049/scratch/frontier/wholeprog   # once
cd ~/rush2049/scratch/frontier/wholeprog && . wp/env.sh    # sets IDO_DIR
wp/reproduce.sh                  # whole matrix, 3 lanes, ~12 min; ends with wp/summary.py

# individual pieces
python3 wp/wp.py inventory       # files, definitions, duplicates
python3 wp/wp.py baseline        # every locked body in its locked recipe
python3 wp/wp.py o3single        # singles alone at -O3
wp/runall.sh full_all    --keep all
wp/runall.sh full_roots  --keep roots
wp/runall.sh full_groups --keep groups
wp/autoblock.sh ab_groups --keep groups         # iterate inline blockers -> wp/block_ab_groups.txt
WP_PREFER_FROM=codex_entity_helpers wp/runall.sh best_raddr --order raddr --keep groups \
    --block wp/block_ab_groups.txt --keep-extra wp/lists/keep_extra.txt \
    --prefer-group-def wp/lists/prefer_group_def.txt
WP_NOCACHE=1 WP_KEEP=1 WP_JOBS=1 wp/runall.sh timing --keep groups   # from-scratch timing
python3 wp/analyze.py RUN --list        # non-matching members, class, first diff words
python3 wp/why.py RUN name...           # lock kind, keep status, retail vs unit callers
python3 wp/inline_edges.py RUN          # umerge inlining vs retail jal (M4)
python3 wp/inline_rule.py               # M3
python3 wp/static_equiv.py              # M6
python3 wp/stubs.py wp/runs/static/zlib_deflate__kp/o.o 800A8000 800AB300   # M5
python3 wp/locality.py best_raddr       # M6 (inconclusive)
python3 wp/mini.py NAME --files a.c b.c --keep f g --members f   # small probes
# M7: two groups that both define sound_update_channel etc.; warnings in wp/runs/mini/dup/log
python3 wp/mini.py dup --files src/blob/groups/codex_sound_channel/group.c \
    src/blob/groups/codex_sound_channel_extra/group.c --keep mode_byte_set --members mode_byte_set
# M8: padN.c = `void __pad(void)` storing to N globals, linked after the group (emitted before it)
python3 wp/mini.py padb2 --files src/blob/groups/codex_task_complete_signal/group.c pad2.c \
    --keep __pad task_complete_signal func_8008AD04 --members task_complete_signal
```

`wp.py build` options: `--set all|singles|groups`, `--ctx keep|strip` (keep or
drop group context definitions), `--keep all|roots|real|groups`, `--standins`
(a generated caller per function with retail callers missing), `--block FILE`,
`--keep-extra FILE`, `--unkeep FILE`, `--prefer-group-def FILE`,
`--order name|addr|raddr`; environment `WP_NOINLINE`, `WP_NOMERGE`,
`WP_NOCACHE`, `WP_KEEP`, `WP_JOBS` (default 4).

The stage commands are those of `tools/cloud/score.py compile_group` /
`blob_group.builder_script` (`cc -j`, `uld -kp keep.txt`, `usplit`, `umerge`,
`uopt`, `ugen`, `as1 -r4300_mul`), with `umerge -v` added to log inlining.
Sources are first passed through IDO `cc -E`, because 378 of them still carry
`#define` / `#if` lines and definitions cannot be found or stripped otherwise.
