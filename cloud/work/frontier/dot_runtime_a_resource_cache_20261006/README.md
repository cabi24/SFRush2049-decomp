## Contract

The routine first returns the earliest matching loaded record, treating
**every nonzero** loaded byte as true. Otherwise it prefers the earliest
matching unloaded record. Only when no id matches does it take the earliest
record with **any negative** id byte. A full array returns zero and preserves
the output word.

Loading calls `audio_frame_sync(kind + 88,1,1,0,null)`, writes the returned
handle to the selected record and caller output, marks it loaded, writes its
low halfword into `D_80142B08[id]`, and calls
`func_800BB02C(id,kind,null)`. It returns one even for a negative handle;
adding an apparent failure check would change the native contract.
The source's signed-halfword inputs give a safe signed32 `kind+88` range
of -32680..32855.

The actual 520-byte loader and 276-byte setup helper are bound by native
body hashes and four native entry/data addresses. Their existing source
contracts are read-only witnesses. The loader source occurs in an accepted
972C4 context group, but neither helper is claimed here as a newly accepted
body. The setup reconstruction is explicitly archived NONMATCH.
No fabricated live-in parameters or helper stubs are compiled into this
candidate.

## Domain and limits

The producer's working domain is id 0..12, valid nonaliasing output/cache/table
storage, synchronous helper boundaries and stable ordinary memory. Its table
has 13 synthetic entries; the related 13-slot initializer does **not** prove
the actual global halfword-table allocation extent. Real use must satisfy the
actual table capacity and both helper preconditions.

All signed-kind endpoints and arbitrary32 returned handles are bounded
O32 argument, ordering and narrowing stress with helper doubles. They do not
prove those values are valid real resources or that loading succeeds.
The independent reviewer also tests wider positive indices using explicitly
enlarged synthetic storage, and negative ids only on paths that do not index
the table. Out-of-range signed narrowing follows the observed two's-complement
GCC/IDO low bits; it is implementation-defined C, not a portability promise.

External helper bodies and whole-game callers are not executed. No unrestricted
alias/pointer, asynchronous mutation, concurrency, hardware, gameplay, original
source/TU, image, compression, full-ROM, hosted CI, acceptance or merge claim.
Native execution means bounded instruction interpretation, not N64 hardware.

### Receipt portability

IDO records absolute source paths in nonallocated ECOFF `.mdebug`, even
with `-g0`. A relocated replay exposed this after the first frozen review.
The correction preserves raw object and `.mdebug` hashes as forensic run
provenance. It additionally fingerprints every other ELF section, bytes,
size, attributes and ABI metadata. The fingerprint helper is reused unchanged
from reviewed PR #131 at commit `31d8af99a3b08a1b52763aef0ecb3c7eb9c1eb65`.
Only physical section offsets and proven nonallocated `.mdebug` payload/size
are excluded from that fingerprint; allocated debug sections are rejected.

All eight object recipes are freshly compiled from identical source at two
differently sized absolute paths. Non-debug ELF fingerprints remain equal;
both raw-object and debug hashes differ, and each debug payload contains its
exact source path once. Code, relocation, symbol/string table, `.reginfo`,
`.options`, ABI and four compiled wrong-source mutants are distinguished.
Portable receipt comparison excludes exactly the candidate/control raw-object
and debug hashes; every other proof field remains binding. Independent raw
object/ELF hashes are likewise forensic run identities; those scripts freshly
audit their full objects and GNU links on each run. No binary or behavior
comparison is relaxed.
