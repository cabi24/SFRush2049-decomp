## Design

**The rule.** A reference to the object's own `.rodata`/`.rdata`/`.lit4`/`.lit8`
/`.data`/`.sdata` is a HI16/LO16 pair against a section symbol. The retail
function has an absolute address in the same two words. `owndata.verify` reads
the retail bytes at that address and requires them to equal the object's bytes
at the relocation's section offset.

- **Window.** Each referenced offset opens a window that ends at the next
  referenced offset of that section (references from every function in the
  object bound it) or at the section end.
- **Length compared.** At least what the instruction loads (8 for
  `ldc1/sdc1/ld/sd`, otherwise 4), and otherwise the window with trailing zero
  bytes removed, rounded up to a word. IDO pads sections to 16 bytes and that
  padding is another owner's data in the image, so it cannot be compared. This
  is the same trade `blob_group._local_data_bases` makes.
- **Jump tables.** Words of the window that carry `R_MIPS_32` relocations are
  mapped first: a `.text` offset inside the function becomes the function's
  image address plus the offset; an entry into another function of the object
  resolves through that function's known address or stays unverified. Any
  other relocation type inside referenced data is a failure.
- **Layout (read-only sections).** Retail `.rodata` is per function, in
  function order. All of one function's references into one read-only section
  must therefore agree on a single section base. Two literals with the right
  values in the wrong order fail, although each load reads an equal value.
- **`.data`.** Checked the same way per object, with no single-base rule
  (retail `.data` is per translation unit), and reported as its own class with
  the address: `own .data verified at 0x801161D0 (4 bytes, all zero; …)`.
- **Never promoted silently.** `.bss` and other uninitialised sections, a
  retail address with no known bytes, an unpaired HI16/LO16, or an unknown
  function address for a jump table leave the reference *unverified*.

**Results** are three lists: proven relocation sites, failures (a concrete
difference: site offset, retail address, retail and compiled bytes) and
unverified references with a reason.

**Scorer (`score_py.patch`).** `compare` calls `owndata.verify` only when
`relocate` reported section-relative references. Failures go to `errors`, so a
wrong literal is refused even with `--allow-unverified`. The unverified list is
cleared only when there are no failures, nothing is left unverified, and every
masked relocation word is a proven site. Verified addresses are printed as
indented note lines under the member; `summary()` stays exactly `MATCH`.

**Splice (`blob_splice.link_function`).** `own_data_placements` runs the same
routine against `build/game_code.bin`, then adds one output section per own
data section at the base retail uses (`.own0 0x80123E74 : SUBALIGN(1) { *(.rodata) }`),
so `ld` produces retail's HI16/LO16 words. The data is not emitted; it already
lives in the image's data run. A checked difference is a `BuildError` naming
the site. For an object with no own-data relocations the function returns
before reading the image and the linker script is byte-for-byte the old one (a
test pins the script text).

## Retail data for the repo-only scorer

The tracked `asm/us/blob/*.s` files hold every function as `.word`s but the
data segment only as `.incbin "build/game_code.bin", 561964, 85108`. The
scorer therefore has no retail `.rodata`/`.data` bytes in a bare checkout.

Proposed tracked artefact: `asm/us/blob_data/opaque.hex` (199,243 bytes of
text) plus `asm/us/blob_data/SHA256SUMS`, generated by

```bash
python3 tools/cloud/owndata.py generate --image build/game_code.bin
python3 tools/cloud/owndata.py check    --image build/game_code.bin
```

The generator checks the image's SHA-256 against `symbols.json`'s
`image_sha256`, walks the region files in order, compares every tracked
`.word` with the image, and dumps each `.incbin` run. `asm/us/blob` is not
touched. The scorer looks for `<targets>_data` beside the target directory,
so `--targets asm/us/ovl_b` simply has no data and behaves as before. A present
artefact that fails its SHA256SUMS is fatal. Both files are generated in this
worktree and were used for the validation below.

## For the reviewer

1. **Apply the patch**: `git apply cloud/work/frontier/rodata/score_py.patch`.
   `test_owndata.py` builds a patched scorer from the patch file until then and
   uses the real scorer afterwards.
2. **Decide whether to track `asm/us/blob_data/`.** It puts 86 KB of retail
   data bytes in the repository as text. Without it the patched scorer behaves
   exactly as today. A rodata-only artefact (4,480 bytes) would cover literals
   and jump tables but not local statics.
3. **Extend the protection hook.** `tools/cloud/owndata.py` and
   `asm/us/blob_data/` are now part of what a strict `MATCH` trusts;
   `.claude/hooks/protect_files.py` does not list them. The artefact's
   SHA256SUMS sits beside it and is no defence against editing both.
4. **All-zero `.data` objects are weak evidence.** `static s32 x = 0;` verifies
   against any zero word inside the image. Both real `.data` cases today are
   of this kind. The note says `all zero`; whether that should count as strict
   is a policy call. The splice image gate still checks the address words.
5. **Zero tails are not compared.** An object whose last bytes are zero is
   compared only up to its last non-zero word (minimum 4 or 8 bytes).
6. **`blob_splice` now imports `tools.cloud.owndata`** (`from ...cloud import
   owndata`), the first import from `tools/conveyor` into `tools/cloud`.
7. **Merge.** The main checkout has an uncommitted one-line change to the
   `.out` line of `link_function` (`SUBALIGN(4)`); this work leaves that line
   alone, but the pinned script text in
   `test_splice_link_without_own_data_is_unchanged…` will need that line updated.
8. `--allow-unverified` no longer admits an own-data reference that was checked
   and differs. CI claims with `"allow_unverified": true` whose literals are
   really wrong will start failing.
9. A single-path splice whose own `.data` objects sit at independent retail
   addresses is refused (`ld` can place a section only once). None seen yet.
