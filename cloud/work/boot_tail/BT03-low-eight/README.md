## Native ABI, data, and extent audit

All eight whole bodies were inspected, including every control-transfer opcode.
None contains a direct or indirect call. No argument is inferred solely from an
inventory jal scan. All eight have ordinary o32 leaf signatures; none reads an
unestablished hidden argument or writes an unsaved callee-saved register. The
only return transfer is through ra. No body uses special cache/cop0 instructions,
local jump tables, or unresolved/section-relative data relocations.

- `148F8` consumes a full-word index in a0 and an input pointer in a1. Native
  byte-pair loads implement four potentially unaligned big-endian unsigned
  halfword reads. IDO's native `__unaligned unsigned short *` qualifier produces
  this sequence without inline assembly or synthetic byte-order helpers. The
  third value is converted through unsigned-to-float, then double arithmetic
  with exactly 1/4096, then stored as float. Both constants are synthesized in
  registers, not fetched from unproved rodata. Caller `22F24` supplies four
  halfwords from its stack buffer and narrows the slot index to eight bits.
  The caller's byte swaps are outside this function and are not replicated.
  Source retains a 104-byte slot, known byte prefix, word +20 and halfword +40,
  extending the local partial layout only at +32, +34 and +36. Unknown arrays
  represent real unrecovered record bytes, not artificial stack padding.
- `14D30` consumes a0 as unsigned 32-bit input, loads `D_8004F800` as signed
  32-bit, and returns an unsigned integer in v0. The native high-bit input
  correction and FCSR-assisted unsigned conversion are emitted naturally by
  IDO. Caller `2300C` passes the absolute magnitude of a signed halfword and
  uses the returned v0 in its sign-restoration path. The global's nonzero
  positive-rate meaning is a hypothesis; no extra source clamp or guard was
  added. Host tests cover well-defined conversions only.
- `171C0` has no inputs or API result. Caller `199F4` invokes it without
  arranging arguments and ignores v0. Native stride 24 and 256 iterations
  establish the array size. Its four-way loop unroll is generated by ordinary
  O2 compilation of a for loop; no manual unrolling was introduced.
- `1729C` consumes a state pointer in a0, accesses list heads +3960 and +3964,
  and has no API result. Callers `18C2C` and `18D40` pass their saved state
  pointer after `1734C` and ignore the result. The active list is prepended
  first and pending list second, preserving each internal order. The global
  free head is `D_80043EB0`; the caller-provided state need not be the current
  state global. List invariants assume null previous pointers at list heads.
- `173B4` has no inputs and returns a nullable node pointer in v0. `17D38`
  checks that return, saves it, and initializes four payload words +8..+20.
  Nodes are 24 bytes, with next at +0 and previous at +4. The current state
  pointer is `D_8004BE80`. The saved head local records a real list pointer
  and supports the original alias-sensitive rereads; it is not a keeper.
- `17410`, `17470`, and `174D0` each take one node pointer in a0 and have no
  API result. Native callers `17D38`, `17540`, and `18184`, respectively,
  provide their current list node and ignore v0. They repair neighboring
  links, update the appropriate head when removing its first node, and
  prepend to the destination list. Destination previous is cleared, and an
  existing destination head's previous points to the moved node. `174D0`
  moves to pending rather than the free list.

## Optimization and directed experiments

All exact sources carry `-g0 -O2 -mips2 -G 0 -non_shared`; the unchanged scorer
adds `-Wab,-r4300_mul`. Frameless leaves, branch-likely list traversal, common
subexpression reuse, and the initializer's automatic unroll support O2. O1
was tried after O2 on each initial source and then again on every final source;
all final O1 controls fail, as recorded above.

Strict initial O2 results ranged from 2/55 words to 42/44, while `14D30`
matched immediately. Before any refinements, `tools/workbench.py diagnose`
ran on canonical-target and fully relocated candidate objects. Its metadata
summary is in `diagnosis.json`; heuristic pass ownership did not authorize
any compiler/scorer changes. Complete initial and directed controls, source
hashes and scores are retained in `controls/` and `experiments.json`.

Refinements were limited to one or two natural variants per nonmatching body:
initialize the previous pointer before storing the global list head; assign
traversal cursor before the null gate; test the next pointer just assigned;
retain a meaningful saved destination-head local; use IDO's explicit
unaligned-halfword input type. No fake formals, padding locals, dummy calls,
inline assembly, forced-register names, function-boundary changes, or blind
flag sweep was used. All eight ended in strict zero; no NONMATCH is hidden.
