# Full-project audit, evidence and plan validation

## Scope and revision

The planning audit used freshly fetched master `53d0fba0c5f44e91fe921f722fee7ff63a2dd0fe` on 2026-10-03. Independent high-effort reviews covered source/coverage architecture, verification/toolchain/operations, archive/PR history, and an ongoing state-source/ABI investigation. The resulting [program plan](../../PROJECT_PLAN.md) and [65 primary work packages and two child packets](2026-10-03-work-packages.md) synthesize those findings.

This is an inventory and sampled deep audit, not a claim that every one of thousands of source variants was manually proven correct. No candidate matching campaign, private ROM gate, accepted-source edit or source integration was performed for this planning commit. The separately published state fragment has its own explicitly narrower tests and evidence.

The audit inspected project rules, constitution, matching/promotion/context skills, Makefile, CI, tests, lock data, protected-target metadata, documented integration receipts, current source inventory, all 619 Markdown archive entries for indexing, selected actual source/recipe/evidence packets, and live PR metadata. It did not infer facts from arbitrary subsystem filenames, historical percentages or source counts.

The plan is documentation-only. It does not amend the constitution, lift the owner's paused target restriction, authorize unrelated PR merges, modify code or replace production acceptance gates.

### A3. Source landscape and its limitations

Fresh master-only conservative inventory over `cloud/`, `src/`, `work/`:

- 4,972 unique C blobs; 10,437 path/blob/definition leads; 4,519 distinct names.
- Of 550 unmatched native IDs, 452 have a same-name nonempty lead, 50 only stub/TODO leads, 48 no same-name lead.
- 541 direct `src/blob/*.c` files; 64 accepted blob group manifests.
- 3,288 C files under `cloud/`; 155 research IPA group manifests.
- 56 legacy `src/game/*.c` files.

These are source/lead counts, not complete functions or coverage. Generic header prefixes and numerous variants greatly inflate file/line counts. The scanner can miss K&R/macros/aliases and include inactive branches. Concrete counterexample: `audio_doppler_calc` appears stub-only by same-name scan yet an old group contains its full K&R string-blitter source. The earlier PR1–45 scan's 5,081 unique blobs describes a different queried ref set; it does not contradict this master-only census.

[Source-inventory documentation](../../cloud/work/source_inventory/README.md) explains its 9 synthetic tests and explicit limitations. P03/P04 add human/native review instead of turning the tool into a false semantic classifier.

### A4. Build and whole-cartridge boundaries

The Makefile can discover generic `src/**/*.c` for optional compilation, but the ROM object path uses generated `src/rom/` translation units, assembly/data and the source-rebuilt game blob. Legacy physics/save/replay/audio/weapon files include simplified models, defaults, illustrative buffers and TODOs. Compiling one does not put that behavior into the original cartridge.

The combined 708,512-byte tracker is not the full cartridge byte count. `splat.us.yaml` retains ROM `[0x10000,0xC00000)` as a broad data segment; the known compressed game stream at `0xB0CB10` is one part. IPL3, assets, textures, models, tracks, audio banks, microcode, runtime images and initialized/unknown data need S13's separate ownership atlas. Function matching and lawful data reconstruction are different work.

## C. Verification findings and concrete reproductions

### C1. Missing accepted objects can silently fall back

Inspection of `tools/conveyor/pipeline/blob_splice.py:spliced_bodies` found paths that skip missing single objects/extents or continue after group/single-link failures. `blob_rom.produce` passes the resulting partial dictionary to TU generation, which can retain passthrough for omitted slots. Lock-count coverage can therefore diverge from fresh source-built-body membership even when the complete linked image remains identical.

A synthetic fixture with one locked target and its compiled object missing returned an empty body dictionary rather than failing. No native target compilation was involved. This demonstrates the missing-object branch; it is not proof that the last accepted build used fallback. The last integration receipt explicitly records 666 complete bodies and prior-lock preservation. V01 makes that existing manually checked invariant mandatory in production.

### C2. Toolchain/cache identity is too weak for long-lived evidence

`tools/cloud/setup.sh` validates the archive on installation, but an existing executable compiler can bypass content verification. Some wrapper caches use compiler size/mtime or process-lifetime environment/target dictionaries rather than all immutable input content.

A synthetic target fixture was loaded through the wrapper, then modified so canonical `score.targets()` rejected its integrity; the already cached wrapper still returned its old targets. No protected repository target was modified and no matching experiment ran. V03/V04 bind identities and invalidate stale evidence. A cache-hit result is not a new integrity verification.

### C3. CI does not currently run every offline test suite

`pytest.ini` points default collection to `tests/conveyor`; the Verify workflow explicitly runs that directory with live-node tests deselected. The 17 `tests/cloud` files are omitted from this default path.

An independent isolated fresh-master run of `python -m pytest tests/cloud -q -rs -p no:cacheprovider` collected 269 tests: **250 passed, 19 skipped**, exit 0. Skips reflected absent local IDO/MIPS/m2c integration capability. This establishes that much of the omitted suite is immediately runnable, not that every cloud integration test passed. V02 adds explicit capability-classified coverage and visible skip reasons.

### C4. Submission routes and research exit states differ

`tools/cloud/check_submissions.py` routes changed `cloud/matches/*.c` and `cloud/work/ipa-groups/<group>/` submissions. Standalone research packets outside those paths depend on their explicitly added tests/replay tools. Claims-only group checking permits unclaimed research to be nonmatching; zero claims or diagnostic compile failure is not a matching result. V05/V06 retain research flexibility while making claims, strict proof and test routing unmistakable.

### C5. Shared integration work is not concurrency-safe by assumption

Blob group/splice stages and some remote scratch/log paths are fixed/shared. Private integration must remain serialized with isolated checkout/staging paths until concurrency is explicitly tested. Static inputs also need their own sync; game-blob sync does not carry every static C/asm/config/storage change. V10 addresses isolation without assuming current LAN access or resetting another contributor's work.

### D4. Runtime identity is more than an address

The archive's [loader packet](../../cloud/work/ipa-groups/codex_heap_load_a14/STATUS.md) documents two loaders sharing `8038A400..803BB380`, selected through different ROM-pointer globals and loaded flags, with different clear ranges. This supports an image-specific provenance investigation. It does not yet identify which loaded image owns each unknown service.

R16 therefore precedes external declarations for C974's 8038D798, viewport 8038FCE0/80390F60, state 8038CA24/803908D0 and collision 8038D3A4. A trusted map/header/implementation must identify active image, exact revision, typed inputs/returns, side effects and compiler visibility. Request minimum text evidence; no raw ROM upload is needed for ordinary archive reconstruction.
