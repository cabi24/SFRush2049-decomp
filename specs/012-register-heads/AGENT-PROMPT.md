## The project in four lines

We are writing C that compiles with SGI IDO 5.3 to a byte-identical *San Francisco Rush 2049* (N64, US) ROM.
The ROM holds static boot/library code and a zlib-compressed **game-code image** (647,072 bytes at 0x80086A50).
Game functions are tracked as *extracted targets* with extents (address + size) in a generated layout; matched C is
spliced back into the image behind an image gate and a full-ROM SHA-1 gate. Coverage is reported as
"functions from C / functions known" and "bytes from C / bytes", and the game and static denominators are
**never merged**.

## Your task

The layout knows 1,165 game functions, but part of the image is still opaque `.incbin` runs (six of them, near
0x8010xxxx) that hold real functions nobody has registered. A cloud analysis found **52 function heads** there:
`cloud/work/unregistered-heads-full.md` (generated by `cloud/work/tools/ipakit/heads.py --json`; the older, shorter
`cloud/work/unregistered-heads.md` is superseded). Your job is to register the ones that are provably complete
functions, through the project's own pipeline, so they become targets the farm and the cloud agents can match.

Deliver, in this order:

1. **A detector in the pipeline, not a copy of the cloud script.** Add `python3 -m tools.conveyor.pipeline.closure heads`
   (dry run by default, `--apply` to write), in the style of the existing `closure orphans`
   (`tools/conveyor/pipeline/closure.py`: `find_orphans`, `_decodes_as_code`, `_branch_lands_in`) and
   `targets.stranded_head` / `targets.falls_through_into` / `targets.populate(names=)` /
   `targets.relocate_extracted(names=)`. Re-derive each head from the extracted image (prologue sweep inside the opaque
   runs plus `jal` and pointer-table evidence). You may read the cloud script for ideas but verify independently
   and record any head where you disagree with it.
2. **A defensible extent for each head**: start at the head, end at the last instruction of the function (all `jr $ra`
   returns and their delay slots accounted for; branch targets stay inside; padding excluded; the next head, a known
   function or the end of the run bounds it). A head whose end you cannot establish, that falls through into another
   function, or that decodes as data in places is **not registered**: list it, with the reason, in
   `specs/012-register-heads/findings.md`.
3. **Registration through the tools**: names `func_XXXXXXXX`, population `extracted`, layout/linker script/region files/
   symbols/prototypes regenerated by their generators (never hand-edited: `asm/us/blob/*.s`, `src/blob/blob.ld`,
   `asm/us/blob/symbols.json`, `asm/us/blob/SHA256SUMS` come from `blob_tu generate` and the layout tool). Read
   `.claude/skills/refresh-game-context/SKILL.md` for the regeneration order. After registration the coordinator database
   (`~/.conveyor/conveyor.db`) must know the new targets with target objects (`targets.populate` / `relocate_extracted`),
   status `unmatched`.
4. **Tests** in `tests/conveyor/` for the detector and extent logic using small synthetic images (no ROM data in tests),
   including at least: a head that falls through, a head with two returns, a head that runs into data, and a run with
   alternating code and data.
5. **Findings**: `specs/012-register-heads/findings.md` with the table (address, size, decision, evidence) and the new
   coverage numbers (functions and bytes, game only, before and after).

## Hard gates (all must pass before you call it done)

- The built ROM is byte-identical: `python3 -m tools.conveyor.pipeline.blob_rom rom` must print `SHA-1 EXACT`.
  Registration only re-labels bytes; it must not change one.
- `python3 -m tools.conveyor.pipeline.blob_splice check` → `0 problems`; `python3 -m tools.conveyor.pipeline.blob_group check`
  → `0 problems`; all 26 locked static functions intact.
- The **already-spliced game functions must stay spliced**: the lock (`blob_matched.lock.json`, 482 entries now) must be
  unchanged except where a registered head legitimately splits or renames a region; report anything else as a bug,
  do not paper over it.
- `python3 -m pytest tests/ -q -p no:cacheprovider --deselect tests/conveyor/integration/test_known_pairings.py`
  exits 0. **Capture pytest's exit code separately (`rc=$?`); never read `$?` after a pipe.**
- `make progress` (or `python3 -m tools.conveyor.pipeline.blob_splice coverage`) shows game coverage with the new
  denominator; do not merge static and game numbers.
