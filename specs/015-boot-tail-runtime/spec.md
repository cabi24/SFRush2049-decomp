# Feature Specification: Boot-segment tail runtime library (412 functions)

**Branch**: helper branches named `dot/boot-tail-<packet>` (one per claimed packet)
**Created**: 2026-10-03 · **Status**: Ready for packet 1. Scoring packets need PR #52 and PR #54 merged.
**Intended executor**: Astra (repo-only dot worker: GitHub checkout, CI with pinned IDO 5.3,
`tools/cloud/score.py`; no ROM, no LAN builder, no Conveyor coordinator)
**Plan cards**: S12 (static slots), P01 (denominators), I01/I02 (reconstruct and match).
I03 and I04 (promotion) stay with the maintainer.

## Problem

The resident boot segment is ROM `0x1000–0x2F4E0`, loaded to `0x80000400–0x8002E8E0`.
The entry stub clears BSS from `0x8002E8E0`. Static coverage counts only ROM
`0x1000–0x10000` (230 functions, 61,440 B). Past that boundary, CPU code continues to
`0x800277D0`. It is followed by RSP microcode (`N64 RSP mixer V1.1`,
`F3DEX.NoN fifo 2.08`) and then data. The data includes libc `vsprintf` strings
("bug in vsprintf: bad base" at `0x8002D53C`, "(null)" at `0x8002D50C`,
"0123456789abcdef" at `0x8002D4F8`, the upper-case digit table at `0x8002D514`) and the
build stamp `07-17-00 02:26:18 MERRILL BLACKOUT`.

`targets.scan_extent` tiles `0x8000F3A4–0x800277D0` into **439 functions, 99,120 B**
(census `cloud/work/s12_boot_tail_census/`). Each tile was compared word for word,
with relocations masked, against decompals ultralib `e24c836` built with IDO 5.3
(versions K and L with Makefile flags; I, J and K at uniform `-O1` and `-O2`):

| Population | Functions | Bytes | Owner |
|---|---:|---:|---|
| Exact ultralib matches (16 in `0x8000F3A4–0x800103A0`; `__osPi/SiRelAccess` at `0x80014650` and `0x8002517C`; three 32 B `__d_to_ll`-family stubs at `0x80014BD8`, `0x80014BF8`, `0x800205E4`) | 21 | 4,048 | maintainer corpus job, **out of scope** |
| Tiles under 16 B, too small to identify | 6 | 60 | identify only (packet 1) |
| **No ultralib match: this spec** | **412** | **95,012** | **Astra** |

The 412 functions span `0x8000F8D0` to `0x800268D0`, with the excluded rows interleaved. By size: 97 are under 64 B,
211 are 64–255 B, 96 are 256–1,023 B and 8 are 1 KB or more (the largest is
`0x800268D0`, 3,840 B). None of them writes an unsaved callee-saved register, so there
is no `-O3` IPA convention and ordinary **single-function matching** applies (unlike
the ovl_a/ovl_b runtime images). The jal scan finds 671 distinct internal
caller→callee edges (770 `jal` instructions in the census) and 54 calls into counted
static code (25 distinct targets). The game image calls 21 of these functions.
**HYPOTHESIS:** this is the developer's own runtime library: a libc printf family, an
audio driver for their own mixer microcode, and memory, thread, message and DMA
services. Libultra-style code was built at `-O1`/`-O2`.

### Context only (not Astra's work)

- `__osPfsRWInode` (`0x8000F3A4`) is cut at ROM `0x10000` in the current static
  layout. Its true extent is 724 B.
- Eight `symbol_addrs.us.txt` names in `0x8000FAC0–0x800100C0` conflict with exact
  ultralib matches (census README table).
- Both need a maintainer fix through splat/layout and the context tooling.

## Scoring targets (exist on PR #54)

The `research/r16-runtime-images` branch (draft PR #54, stacked on PR #52) contains:

- `asm/us/boot_tail/`: `boot_tail_8000f3a4.s` (one `.text.func_XXXXXXXX` section of
  `.word`s per function), `symbols.json`, `extents.json` and `SHA256SUMS`. It covers
  439 functions, `0x8000F3A4–0x800277D0`, with per-function start evidence, 5
  recognised switch tables, zero unproven merges and zero call targets inside a
  function. Its 32 evidence-free tiles are standalone leaves. It was generated by
  `python3 -m tools.conveyor.pipeline.ovl_targets generate --image boot_tail`.
  Extents are identical to this spec's `inventory.json`.
- CI rescoring of `cloud/matches/boot_tail/*.c` against `asm/us/boot_tail`
  (`tools/cloud/check_submissions.py`, `RUNTIME_IMAGES` includes `boot_tail`).
- `cloud/matches/boot_tail/func_80010A00.c` (`u8` getter of `D_8002C630`) is already a
  true match. It proves the pipeline and is **done**, so it is not an open target.

Scoring command:

```bash
python3 tools/cloud/score.py fn cloud/matches/boot_tail/func_XXXXXXXX.c func_XXXXXXXX \
    --targets asm/us/boot_tail --flags '-g0 -O2 -mips2 -G 0 -non_shared'
```

The scorer always adds `-Wab,-r4300_mul`. Data references resolve through the
address-spelled fallback (`D_XXXXXXXX`), and calls resolve to `func_XXXXXXXX`. Calls
into counted static code use the static names in `symbols.json` or the address-spelled
form.

**Prerequisite:** the owner must merge PR #52 and then PR #54 before any scoring
packet starts. Packet 1 does not need the targets and can start now from master
using `inventory.json`.

## Scope

**In scope:** the 412 `in_scope` rows of [inventory.json](inventory.json), as follows:

- identification and clustering into likely translation units;
- natural C89/IDO C that is a true-zero match for each function;
- per-function compiler-flag evidence;
- a running inventory/status file;
- research notes for nonmatches.

**Out of scope (do not touch):**

- The 21 `ultralib_identified` functions (corpus job) and the `__osPfsRWInode` extent.
- `symbol_addrs.us.txt` and name corrections, splat/`layout`/linker scripts, and static
  denominator changes.
- Static `lock`/`promote`, `matched.lock.json`, `blob_matched.lock.json` and any
  `*.lock.json`.
- Generated targets: `asm/us/boot_tail/`, `asm/us/blob/`, `asm/us/ovl_*`. Treat them
  as read-only ground truth even where `guard_paths.py` does not yet protect them.
- The runtime images ovl_a/ovl_b and their matches.
- Production gates (`blob_splice`, `blob_rom`, `ovl_rom`, `make test`, ROM SHA-1) and
  coverage percentages.
- `include/game_types.h` and `disasm.GAME_SYMBOLS` (propose changes in a note instead).
- RSP microcode and boot data past `0x800277D0`.

Promotion into the cartridge needs a maintainer extension of the static layout to
`0x800277D0`. Astra's deliverable is **verified matching C plus research**, not
coverage.

## User stories

### US1: Identify and cluster (P1, starts now)

As the coordinator, I need the 412 functions grouped into likely translation units with
name hypotheses, so that matching can proceed one cluster at a time with shared types.

**Acceptance:**

1. Every in-scope function is assigned to exactly one cluster with an address interval.
2. Each cluster has a role hypothesis and an evidence label (see Evidence rules).
3. The printf family is located from the data strings and from format-character
   switch/compare evidence.
4. Hand-written assembly candidates are flagged as non-C. Examples: `bcmp` at
   `0x8000F8D0`, the 6 stubs and anything using `cache`, `mtc0`/`mfc0`, `eret` or
   delay-slot tricks IDO never emits.
5. Every reference-source comparison is cited with path, licence and revision. No
   third-party source is vendored without a compatible licence.

### US2: Match small functions (P1, after PR #54)

As a maintainer, I need true-zero matches of the <256 B functions so that one later
layout extension promotes a large batch.

**Acceptance:**

1. Each match is `cloud/matches/boot_tail/func_XXXXXXXX.c` with line 1
   `/* flags: <exact flags> */`. It is self-contained C89, and `score.py` reports MATCH
   for it locally and in CI.
2. Each match has an inventory row updated to `verified_body` with its flags.
3. No artificial constructs (see Matching rules).

### US3: Match medium and large functions by cluster (P2)

As a maintainer, I need cluster-coherent sources for the 256 B+ functions, with shared
types declared consistently. Large (≥1 KB) bodies need reconstruction notes.

**Acceptance:**

1. The same as US2, per function.
2. Every nonmatch is archived under `cloud/work/boot_tail/<cluster>/` with a NONMATCH
   label, its differing-word count, the flags tried and one next hypothesis.

### US4: Running status (P1, continuous)

As the coordinator, I need a single status file so that claims, progress and blockers
are visible without reading PRs.

**Acceptance:** `cloud/work/boot_tail/STATUS.csv` (plus `README.md`) has one row per
in-scope function. Columns:

- `address`, `name`, `size`, `cluster`;
- `name_hypothesis`, `evidence_level`;
- `status` (`open|claimed|nonmatch|verified_body|non_c|excluded`), `owner`;
- `flags`, `diff_words`;
- `source_path`, `pr`, `note`.

Totals in the README separate verified bytes from research. The file never claims
cartridge coverage.

## Matching rules

- **True score zero only.** Strict relocated full-word equality from `score.py`,
  including stack offsets, frame size and no excess words. Relocation-blind or masked
  zero is a lead, not a match.
- **C89/IDO 5.3 only.** No C99 features: no `//` comments, no mixed declarations, no
  `inline`.
- **Natural source.** No fake keeper variables, invented extra formals, padding
  locals, dummy calls or `asm` blocks, and no splitting or merging of native function
  boundaries. Callees are declared, not stubbed into the file with bodies.
- **Flag evidence per function.** Start with `-g0 -O2 -mips2 -G 0 -non_shared`, then
  `-O1`. If both fail, record why. Do not sweep flags blindly: record which native
  signature (frame for leaves, argument spills, `beql`/`bnel`, CSE) supports the chosen
  level. A cluster is expected to share flags; flag disagreement inside a cluster is
  evidence and must be noted.
- **Switch tables and local rodata.** Five functions have recognised jump tables, and
  others may load float/double literals. If the scorer cannot resolve a table or
  literal relocation, record it as `needs-rodata-proof` and escalate. Do not edit the
  scorer or targets to close it.
- **No ROM bytes.** Commit no ROM, decompressed image, raw disassembly dumps or object
  files. The committed `.word` targets are the only ground truth. Addresses, sizes and
  short instruction excerpts in notes are fine.
- **Protected paths.** A PR that changes any out-of-scope path is rejected.
- **Bounded effort.** Spend one working session or about 20 directed variants per
  hypothesis (PROJECT_PLAN §5 and dot_handoff). Extend only for measured movement or
  new native evidence. On a near-match, run `python3 tools/workbench.py diagnose` before
  any further variants.

## Evidence rules

Use the PROJECT_PLAN §1 levels:

- `HYPOTHESIS`: a name or role guessed from structure, strings or neighbours.
- `SOURCE-LEAD`: a matching definition was found in a cited reference.
- `PARTIAL-SOURCE`: some regions reconstructed, missing regions listed.
- `COMPLETE-NONMATCH`: the whole body exists with a residual.
- `VERIFIED-BODY`: true-zero `score.py` MATCH on current master plus CI.

`ACCEPTED` is reserved for maintainer integration. Names in `inventory.json`
(`symbol_addrs_name`) are historical labels, not evidence. Arcade source
(`reference/repos/rushtherock/`) is not in the repo. Request a specific
lookup from the maintainer as an `EXTERNAL-INPUT` note, and do not cite it from
memory.

## Stop and escalate

Stop the packet and record the blocker in `STATUS.csv`/README and `dot_handoff.md` when:

- targets are missing or `SHA256SUMS` fails, or PR #52/#54 is not merged (scoring
  packets only);
- a function's extent looks wrong (a call lands mid-function, or a tile clearly holds
  two functions or half of one). Report it and do not edit targets;
- the function is hand-written assembly or uses instructions IDO cannot emit. Mark it
  `non_c`;
- a match needs a scorer, target, lock or layout change;
- a function turns out to be an ultralib/libc variant that the census should have
  caught. Report it for the corpus job;
- shared-type decisions conflict with existing `include/` headers. Propose the change
  in a note instead;
- a hypothesis reaches the effort bound with no movement.
